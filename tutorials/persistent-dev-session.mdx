---
title: Persistent dev session
description: Start a long-running process in a managed session, disconnect on purpose, and reattach later
---

A [session](/concepts/sessions) is a named process that outlives your connection and replays what it produced while nobody was attached.

<Steps>
  <Step title="Create a sandbox">
    ```shell
    bonya create worker
    ```
  </Step>

  <Step title="Start a managed session">
    ```shell
    bonya session create worker dev -- sh -c 'i=0; while true; do i=$((i+1)); echo tick $i; sleep 1; done'
    ```

    ```console
    NAME         dev
    STATUS       idle
    COMMAND      sh -c i=0; while true; do i=$((i+1)); echo tick $i; sleep 1; done
    WORKING DIR
    ```
  </Step>

  <Step title="Attach, watch it, then detach without killing it">
    ```shell
    bonya session attach worker dev
    ```

    ```console
    tick 1
    tick 2
    tick 3
    ```

    You get the output the session produced before you attached. Detach (or lose your connection) and the process keeps running. Two minutes without typing also detaches an interactive attach.
  </Step>

  <Step title="Confirm it's still running from a fresh terminal">
    ```shell
    bonya session list worker
    ```

    ```console
    NAME  STATUS  ATTACHED  COMMAND                           STARTED
    dev   idle    no        sh -c i=0; while true; do i=$((…  2026-11-10 01:05
    ```
  </Step>

  <Step title="Reattach">
    A sandbox pauses on its own when idle, and attaching wakes it. Run the same command to pick up where you left off:

    ```shell
    bonya session attach worker dev
    ```

    A sandbox you paused explicitly stays paused until you wake it with keepalive (see [Sandboxes](/concepts/sandboxes#lifecycle-states)).
  </Step>

  <Step title="Kill the session">
    ```shell
    bonya session kill worker dev
    ```

    ```console
    NAME         dev
    STATUS       killed
    ```
  </Step>

  <Step title="Clean up">
    ```shell
    bonya delete worker --force
    ```
  </Step>
</Steps>
