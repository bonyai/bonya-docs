The server registers 63 tools across 12 groups. Every tool takes and returns plain JSON — ids, not objects, are how you chain calls together (e.g. `sandbox_create` → its `sandbox_id` → `sandbox_exec`).

<Note>
Results are returned as pretty-printed JSON text. Errors are returned as MCP tool errors (`isError: true`) formatted as `Bonya API error <status> (<code>): <detail>`, using the `code`/`detail` fields from the API's RFC 9457 problem+json error body.
</Note>

## Sandboxes

Create and manage isolated compute environments.

### `sandbox_create`

Create a new sandbox (an isolated cloud compute environment) from a template. By default returns immediately with the sandbox in 'creating' state (202); pass wait=true to block until it is ready (201).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `template_id` | string | no | Optional template id. Omit to use the deployment default. Use template_list to discover available templates. |
| `template_version` | string | no | Optional specific template version. Defaults to the template's latest. |
| `name` | string | no | Optional display label (not unique; every lookup is by sandbox_id). |
| `snapshot` | string | no | Optional snapshot id to restore the new sandbox from (see snapshot_list). |
| `image` | string | no | Optional public OCI image reference (tag or digest) to create the sandbox from instead of a template. Cannot be combined with snapshot, template_id or template_version. Required for GPU sandboxes unless an image template is used. |
| `gpu` | object | no | Optional GPU request, for a GPU sandbox. Pick a type/count from sandbox_gpu_options (an empty list means no GPU capacity is available). Requires an `image` (or an image template); cannot be combined with snapshot or template_version. Subject to the organization's concurrent-GPU limit. |
| `network` | object | no | Network egress policy for the sandbox. |
| `env` | object | no | Optional environment variables set in the sandbox. |
| `secret_sets` | string[] | no | Optional secret set names to inject into the sandbox (see secret_set_list). |
| `wait` | boolean | no | If true, block until the sandbox is ready instead of returning immediately. |

### `sandbox_list`

List sandboxes, optionally filtered by state. Paginated.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `page_size` | integer | no | Page size (default 50). |
| `page_token` | string | no | Pagination token from a previous response. |
| `states` | `creating` \| `running` \| `warm` \| `cooling` \| `cold` \| `waking` \| `deleting` \| `failed` \| `lost`[] | no | Filter to these states. Deleted sandboxes are not listed. |
| `include_disposable` | boolean | no | Include disposable (job-created) sandboxes in the listing. |

### `sandbox_get`

Fetch the current state of a single sandbox by id.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id (e.g. as returned by sandbox_create or sandbox_list). |

### `sandbox_delete`

Permanently and synchronously delete a sandbox. Deleting an already-deleted sandbox succeeds (idempotent). This cannot be undone.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id (e.g. as returned by sandbox_create or sandbox_list). |

## Lifecycle, network & GPU

Pause, keep awake (which also wakes a paused sandbox), restrict egress, fork, and see GPU capacity.

### `sandbox_pause`

Force a sandbox to pause. 'warm' keeps it quick to resume; 'cold' frees more resources but resumes slower. Returns once the stage is reached. A paused sandbox wakes on sandbox_keepalive, on exec/file access, or on incoming traffic.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id (e.g. as returned by sandbox_create or sandbox_list). |
| `stage` | `warm` \| `cold` | yes | Pause stage. |

### `sandbox_keepalive`

Place an expiring keep-awake hold on a sandbox so it is not auto-paused; a paused sandbox is woken. Returns keepalive_until.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id (e.g. as returned by sandbox_create or sandbox_list). |
| `for` | string | yes | Hold duration as a Go-style duration, e.g. "30m" or "2h". |

### `sandbox_network_update`

Replace the network egress policy of a running sandbox (open, allowlist of domains/CIDRs, or airgap).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id (e.g. as returned by sandbox_create or sandbox_list). |
| `mode` | `open` \| `allowlist` \| `airgap` | yes | open = unrestricted egress (default); allowlist = only the 'allow' destinations; airgap = no network. |
| `allow` | object[] | no | Allowed destinations; used when mode is 'allowlist'. |

### `sandbox_gpu_options`

List the GPU type/count combinations currently available for GPU sandboxes (the 'gpu' parameter of sandbox_create, which also needs an 'image'). An empty list means no GPU capacity is configured.

_No parameters._

### `sandbox_fork`

Create N new sandboxes that start with the source sandbox's memory and disk, on the same node. Each child is a separate sandbox you must delete when done.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id (e.g. as returned by sandbox_create or sandbox_list). |
| `count` | integer | yes | Number of forks to create. |

## Exec & filesystem

Run buffered commands and work with files.

### `sandbox_exec`

Run a command in a sandbox and wait for it to finish (buffered, non-interactive). Returns exit code, stdout, and stderr. For long-running or interactive processes, use session_create instead.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id. |
| `cmd` | string[] | yes | Command and arguments, e.g. ["bash","-lc","echo hi"] or ["ls","-la"]. |
| `path` | string | no | Working directory inside the sandbox. |
| `env` | object | no | Extra environment variables. |
| `timeout_s` | integer | no | Max seconds to wait for the command to finish (1-300). |
| `stdin_b64` | string | no | Base64-encoded bytes to write to the command's stdin. |
| `output_encoding` | `utf8` \| `base64` | no | Encoding for the returned stdout/stderr. Defaults to utf8. |

### `fs_read`

Read a file's raw bytes from a sandbox and return its UTF-8 text content.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id. |

| Parameter | Type | Required | Description |

| Parameter | Type | Required | Description |

| Parameter | Type | Required | Description |

## Sessions

Long-lived named background processes.

### `session_create`

Create a named, long-lived session running a command in a sandbox. Unlike sandbox_exec, the session keeps running in the background; use session_list to check on it and session_kill to stop it. Creating a session with a name that already has a live session fails with session_exists (409) unless replace is set, which replaces a terminal (finished) session of the same name.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id. |
| `name` | string | yes | The session name (unique per sandbox). |
| `cmd` | string[] | yes | Command and arguments, e.g. ["bash","-lc","npm run dev"]. |
| `path` | string | no | Working directory inside the sandbox. |
| `env` | object | no | Extra environment variables. |
| `cols` | integer | no | Terminal columns. |
| `rows` | integer | no | Terminal rows. |
| `replace` | boolean | no | Replace an existing terminal (finished) session of the same name. |

### `session_list`

List sessions for a sandbox. Never wakes a suspended sandbox; a suspended sandbox answers from its suspend snapshot (sandbox_suspended: true in the response).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id. |

### `session_kill`

Terminate a named session. Sends a signal (default TERM) and, after grace_ms, escalates. Returns the session's resulting state.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sandbox_id` | string | yes | The sandbox id. |
| `session_name` | string | yes | The session name (unique per sandbox). |
| `signal` | `TERM` \| `KILL` \| `INT` \| `HUP` | no | Signal to send (default TERM). |
| `grace_ms` | integer | no | Grace period before escalation in ms (default 5000, max 60000). |

## Jobs

## Not exposed as tools

<Note>
The API's WebSocket endpoints (TTY `exec` and session `attach`) are not exposed as tools — they don't fit a request/response MCP tool. `sandbox_exec` covers non-interactive commands through the buffered `POST .../exec` endpoint, and `session_create` covers long-running background processes. Identity management (creating organizations, members, invites and API keys) is not available to API keys and is not exposed.
</Note>

## Gotchas

- **Sandbox capacity is capped per account.** If `sandbox_create` or `job_create`'s `new_sandbox` path returns `429 rate_limited`, free a slot with `sandbox_delete` or wait for a job-created sandbox to finish rather than retrying immediately.
- **`session_kill`'s parameter is `session_name`**, not `name` — easy to get wrong since `session_create` takes `name`.
- **A job's `disposition` only applies to a sandbox the job itself created.** The default is `delete`, so a job-created sandbox disappears once the run ends, however it ends (including on `job_cancel`).
- **Secret sets are referenced by name**, not id, in `secret_sets` on templates, sandboxes and jobs.
- **GPU sandboxes** need an `image` (or an image template) and available org GPU quota; check `sandbox_gpu_options`.
- **Preview grant tokens are shown once**, in the response that creates them.
- **Errors are RFC 9457 `problem+json`**, surfaced as `Bonya API error <status> (<code>): <message>`. The `code` is the stable machine-readable part.
