## `bonya session`

<Info>Aliases: `sess`, `s`</Info>

A session is a named terminal process that outlives your connection and replays what it produced while nobody was attached. See [Sessions](/concepts/sessions).

## `create`

```shell
bonya session create [sandbox] <name> [--cols N] [--rows N] -- cmd [args...]
```

Session names match `^[a-z][a-z0-9-]{0,31}$`.

```console
$ bonya session create docs-probe web -- python3 -m http.server 3000
NAME         web
STATUS       idle
COMMAND      python3 -m http.server 3000
WORKING DIR
```

## `list`

```console
$ bonya session list docs-probe
NAME  STATUS  ATTACHED  COMMAND                      STARTED
web   idle    no        python3 -m http.server 3000  2026-11-10 00:56
```

## `attach`

```shell
bonya session attach [sandbox] <name>
```

From a terminal this is fully interactive: stdin is forwarded and window resizes are propagated. Piped or redirected, it streams the session's output read-only, so `bonya session attach web dev | tee log` works.

Detaching leaves the session running. Attaching preempts any other client already attached. From a terminal, two minutes without typing detach, so a forgotten attach does not keep the sandbox awake.

## `kill`

```shell
bonya session kill [sandbox] <name> [--signal TERM] [--grace-ms 5000]
```

Sends the signal, then kills the process group after the grace period.
