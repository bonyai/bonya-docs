## `bonya create [name]`

<Info>Aliases: `new`, `c`</Info>

Starts a new sandbox from the default template, a public container image, or a snapshot, and returns once it is running.

```shell
bonya create                                  # generated name
bonya create web                              # named "web"
bonya create python --image python:3.12-slim  # from a public image
bonya create web --snapshot snp-0a1b2c3d4e5f6g  # restore a snapshot's files
```

The name is optional and **positional**. Leave it out and the service generates a friendly one (like `winter-canyon-278e`). Names are not unique.

## Flags

| Flag | Default | Description |
| --- | --- | --- |
| `--image` | — | A public container image reference (tag or digest). Cannot be combined with `--snapshot`. |
| `--snapshot` | — | A snapshot id to restore the sandbox's files from. |
| `--name` | — | Display name. Prefer the positional form. |
| `--idempotency-key` | — | Idempotency key for the create request. |

A real create looks like this:

```console
$ bonya create docs-probe
ID       sb-iwmjfuuyixl300
NAME     docs-probe
STATUS   running
SOURCE   bonya-dev-x86_64-xeon8358-1c1024m-v1
SIZE     1 vCPU, 1024 MiB
CREATED  2026-11-10 00:56

Open a shell with:
  bonya console docs-probe
```

On an interactive terminal, `create` offers to open a console right away. That offer is skipped, and the hint above is printed instead, under `--json`, `--no-input`, or any non-interactive session.

<Note>
The CLI creates sandboxes from the default template, an image, or a snapshot. To create from a saved template, or to request a GPU, set a network policy or inject secret sets, use the [SDKs](/sdks/typescript/usage) or the [REST API](/api-reference).
</Note>
