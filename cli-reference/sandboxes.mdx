This page covers the **Sandboxes** command group: `list`, `get`, `delete`, and `exec`. For creating a sandbox, see [`create`](/cli-reference/create); for a shell, see [`console`](/cli-reference/console). Jobs, schedules and templates have their own pages: [`job`](/cli-reference/job), [`schedule`](/cli-reference/schedule) and [`template`](/cli-reference/template).

## `bonya list`

<Info>Aliases: `ls`, `l`</Info>

```shell
bonya list [--state running,warm] [--name web] [--limit 20]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--state` | (all) | Comma-separated state filter. Valid values: `creating`, `running`, `cooling`, `warm`, `cold`, `waking`, `failed`, `deleting`, `lost`. |
| `--name` | (all) | Only list sandboxes with this exact (case-sensitive) name. |
| `--limit` | `0` (unlimited) | Maximum number of sandboxes to return. |

```console
$ bonya list
ID                 NAME                STATUS   SOURCE                                CREATED
sb-iwmjfuuyixl300  docs-probe          running  bonya-dev-x86_64-xeon8358-1c1024m-v1  2026-11-10 00:56
sb-bpyk22c3ei3hfx  winter-canyon-278e  cold     bonya-dev-x86_64-xeon8358-1c1024m-v1  2026-11-08 21:05
```

`SOURCE` is the image or template version the sandbox started from. Deleted sandboxes are never listed.

With `--json`, each entry has `id`, `name`, `state`, `template_version`, `vcpus`, `memory_mib` and `created_at`:

```shell
bonya list --json | jq -r '.[] | select(.state=="running") | .id'
```

## `bonya get [sandbox]`

<Info>Aliases: `show`, `info`</Info>

Shows one sandbox's details.

```console
$ bonya get docs-probe
ID       sb-iwmjfuuyixl300
NAME     docs-probe
STATUS   running
SOURCE   bonya-dev-x86_64-xeon8358-1c1024m-v1
SIZE     1 vCPU, 1024 MiB
CREATED  2026-11-10 00:56
```

## `bonya delete [sandbox]`

<Info>Aliases: `rm`, `del`</Info>

Deletes a sandbox. This is not reversible, so an interactive terminal asks for confirmation first.

| Flag | Description |
| --- | --- |
| `--force` | Skip the confirmation prompt. Non-interactively there is no prompt, so naming the sandbox is the confirmation. |

```shell
bonya delete docs-probe --force
```

## `bonya exec [sandbox] [flags] -- cmd [args...]`

<Info>Aliases: `run`, `x`</Info>

Runs a command in a sandbox, prints its output, and exits with the remote command's exit code.

```shell
bonya exec web -- ls /root
bonya exec -- ls /root        # prompts for the sandbox
tar -c . | bonya exec web -- tar -x -C /tmp
bonya exec web --tty -- bash  # interactive
```

| Flag | Default | Description |
| --- | --- | --- |
| `--env KEY=VALUE` | — | Environment variable (repeatable). |
| `--cwd` | `/` | Remote working directory. |
| `--tty` | off | Allocate a pseudo-TTY and forward stdin interactively; resizing your window resizes the remote terminal. |
| `--no-stdin`, `-n` | off | Don't forward piped stdin. Use it inside a `while read` loop. |
| `--timeout` | none | Stop the command after this long, e.g. `10m`. The sandbox enforces it even if the CLI goes away. Exit code `124`. |
| `--cols`, `--rows` | your terminal | TTY size (requires `--tty`). |

Piped stdin is forwarded to the command and closed at its end. Ctrl-C or SIGTERM stops the remote command.

<Note>
A command starts in `/` as `root`, with `HOME=/root`. Use `--cwd` to start somewhere else.
</Note>
