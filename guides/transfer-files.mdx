---
title: Transfer files
description: Upload, download, list, and inspect files on a sandbox
---

Every sandbox exposes a filesystem API under `/v1/sandbox/{sandbox_id}/fs`. Read and write bodies are **raw bytes** — not tar archives, not multipart form data — so each call moves exactly one file. See [Files](/concepts/files) for the full field reference; this guide is workflow-focused.

## Upload a file

<CodeGroup>
```shell cURL
curl -s -X PUT "https://api.bonya.ai/v1/sandbox/$SANDBOX_ID/fs/write?path=/root/hello.txt" \
  -H "Authorization: Bearer $BONYA_API_KEY" \
  -H "Content-Type: application/octet-stream" \
  --data-binary @./hello.txt
```

```shell CLI
bonya fs upload web ./hello.txt /root/hello.txt
```

```ts TypeScript
await sandbox.uploadFile("./hello.txt", "/root/hello.txt");
```

```python Python
sandbox.upload_file("./hello.txt", "/root/hello.txt")
```

```go Go
sandbox.Upload(ctx, "./hello.txt", "/root/hello.txt")
```
</CodeGroup>

`fs/write` returns `204` with no body on success. The SDKs stream in 64 KiB chunks through a guest-side temp file and publish atomically, so a reader never observes a partially written file.

## Download a file

<CodeGroup>
```shell cURL
curl -s "https://api.bonya.ai/v1/sandbox/$SANDBOX_ID/fs/read?path=/root/hello.txt" \
  -H "Authorization: Bearer $BONYA_API_KEY" \
  -o ./hello.downloaded.txt
```

```shell CLI
bonya fs download web /root/hello.txt ./hello.downloaded.txt
```

```ts TypeScript
await sandbox.downloadFile("/root/hello.txt", "./hello.downloaded.txt");
```

```python Python
sandbox.download_file("/root/hello.txt", "./hello.downloaded.txt")
```

```go Go
sandbox.Download(ctx, "/root/hello.txt", "./hello.downloaded.txt")
```
</CodeGroup>

`fs/read` returns the raw bytes as `application/octet-stream` — there's no envelope to unwrap.

<Note>
There's no directory/tar transfer mode in this API. `upload`/`download` (CLI and SDKs) and `fs/read`/`fs/write` (REST) each move exactly one file. To move a directory tree, upload or download its files individually, or run a command via [exec](/guides/run-a-command) that packs/unpacks an archive on the sandbox side.
</Note>

## Write small content directly

For short text content you don't want to stage as a local file first, `read`/`write` on the SDK take bytes or a string directly rather than a file path:

<CodeGroup>
```ts TypeScript
await sandbox.writeFile("/root/message.txt", "hello\n");
const payload = await sandbox.readFile("/root/message.txt");
```

```python Python
sandbox.write_file("/root/message.txt", "hello\n")
payload = sandbox.read_file("/root/message.txt")
```
</CodeGroup>

## List a directory

<CodeGroup>
```shell cURL
curl -s "https://api.bonya.ai/v1/sandbox/$SANDBOX_ID/fs/list?path=/root" \
  -H "Authorization: Bearer $BONYA_API_KEY"
```

```shell CLI
bonya fs ls web /root
```

```ts TypeScript
const entries = await sandbox.listFiles("/root");
```

```python Python
entries = sandbox.list_files("/root")
```
</CodeGroup>

The response is `{ "files": [ ...FsFileInfo ] }` — immediate children only, sorted by name, each carrying `path`, `name`, `kind` (`FILE`/`DIRECTORY`/`SYMLINK`/`OTHER`), `size`, `mode`, and `modified_at_unix_nanos`.

## Stat a file

<CodeGroup>
```shell cURL
curl -s "https://api.bonya.ai/v1/sandbox/$SANDBOX_ID/fs/stat?path=/root/hello.txt" \
  -H "Authorization: Bearer $BONYA_API_KEY"
```

```shell CLI
bonya fs stat web /root/hello.txt
```

```ts TypeScript
const info = await sandbox.statFile("/root/hello.txt");
```

```python Python
info = sandbox.stat_file("/root/hello.txt")
```
</CodeGroup>

`stat` returns lstat-style metadata — a symlink is reported as a symlink, not followed.

## Directories, renaming, and deleting

<CodeGroup>
```shell cURL
# mkdir
curl -s -X POST "https://api.bonya.ai/v1/sandbox/$SANDBOX_ID/fs/mkdir" \
  -H "Authorization: Bearer $BONYA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"path": "/root/output"}'

# rename
curl -s -X POST "https://api.bonya.ai/v1/sandbox/$SANDBOX_ID/fs/rename" \
  -H "Authorization: Bearer $BONYA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"from": "/root/hello.txt", "to": "/root/output/hello.txt"}'

# delete (recursive)
curl -s -X DELETE "https://api.bonya.ai/v1/sandbox/$SANDBOX_ID/fs?path=/root/output&recursive=true" \
  -H "Authorization: Bearer $BONYA_API_KEY"
```

```shell CLI
bonya fs mkdir $SANDBOX_ID /root/output
bonya fs mv $SANDBOX_ID /root/hello.txt /root/output/hello.txt
bonya fs rm $SANDBOX_ID /root/output --recursive
```

```ts TypeScript
await sandbox.mkdirFile("/root/output");
await sandbox.moveFile("/root/hello.txt", "/root/output/hello.txt");
await sandbox.removeFile("/root/output", true);
```

```python Python
sandbox.mkdir_file("/root/output")
sandbox.move_file("/root/hello.txt", "/root/output/hello.txt")
sandbox.remove_file("/root/output", recursive=True)
```
</CodeGroup>

`move`/`rename` is same-filesystem and atomic — it doesn't overwrite an existing destination, and won't move across filesystems. `remove` with `recursive` set removes a non-empty directory without following symlinks.
