---
title: Templates
description: Saved, versioned launch configurations for your organization
---

A **template** is a saved launch configuration: an image, resources, environment, secrets, network policy and previews. Templates belong to your organization and are versioned: changing the configuration publishes a new immutable `revision`.

You don't need a template to create a sandbox. An empty `POST /v1/sandbox` uses the deployment's default image, and `image` starts from any public OCI image. Templates are for launch settings you want to reuse.

## Managing templates

<CodeGroup>
```shell cURL
curl -s -X POST "https://api.bonya.ai/v1/templates" \
  -H "Authorization: Bearer $BONYA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "node-dev", "config": {"image": "node:22", "cpu": 2, "memory_mib": 4096}}'
```

```ts TypeScript
const template = await client.createTemplate({
  name: "node-dev",
  config: { image: "node:22", cpu: 2, memoryMib: 4096 },
});
const all = await client.listTemplates();
await client.updateTemplate(template.id, { config: { image: "node:22", cpu: 4 } }); // revision 2
await client.deleteTemplate(template.id);
```

```python Python
template = client.create_template(
    "node-dev",
    config=TemplateConfig(image="node:22", cpu=2, memory_mib=4096),
)
all_templates = client.list_templates()
client.update_template(template.id, config=TemplateConfig(image="node:22", cpu=4))  # revision 2
client.delete_template(template.id)
```
</CodeGroup>

| Endpoint | Description |
| --- | --- |
| `GET /v1/templates` | List templates, each at its latest revision. |
| `POST /v1/templates` | Validate the configuration, resolve the image to a digest, and publish revision 1. |
| `GET /v1/templates/{template_id}` | Get a template. Pass `?revision=N` for an older revision. |
| `PATCH /v1/templates/{template_id}` | Omitted fields keep their value. Changing the configuration publishes a new revision. |
| `DELETE /v1/templates/{template_id}` | Delete a template. |

**MCP:** `template_list`, `template_get`, `template_create`, `template_update`, `template_delete`. The CLI can browse templates with [`bonya template list`](/cli-reference/template).

## Configuration

| Field | Description |
| --- | --- |
| `image` | OCI image reference. The service resolves it to `image_digest` on save. |
| `registry_connection_id` | A [registry connection](/concepts/secrets#registry-connections) for a private image. |
| `cpu`, `memory_mib`, `disk_gib` | Resources. |
| `env` | Environment variables. |
| `secret_bindings` | Maps an environment variable name to a [secret](/concepts/secrets) id. |
| `secret_sets` | [Secret set](/concepts/secrets#secret-sets) **names** injected as environment variables. |
| `entrypoint`, `command` | `null` inherits the image default; an array overrides it. |
| `working_dir` | Working directory. |
| `network` | A [network policy](/concepts/sandboxes#network-policy). |
| `previews` | Ports to publish on start. |

A template contains secret **references**, never values.

## Creating from a template

Set `template_id` (and optionally `template_revision`) when you [create a sandbox](/concepts/sandboxes#creating-a-sandbox):

```json
{ "template_id": "tpl-...", "template_revision": 2 }
```

A job's `new_sandbox` spec accepts the same fields. See [Jobs](/concepts/jobs).
