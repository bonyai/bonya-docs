---
title: Errors
description: How the Bonya API reports failures
---

Every non-2xx response from the Bonya API is an [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) `application/problem+json` body.

## Shape

```json
{
  "type": "urn:bonya:problem:lifecycle_conflict",
  "title": "Lifecycle state conflict",
  "status": 409,
  "code": "lifecycle_conflict",
  "detail": "session \"dev\" is running or attached"
}
```

<ResponseField name="type" type="string" required>
  A URI identifying the problem type.
</ResponseField>

<ResponseField name="title" type="string" required>
  A short, human-readable summary of the problem.
</ResponseField>

<ResponseField name="status" type="integer" required>
  The HTTP status code, repeated in the body for convenience.
</ResponseField>

<ResponseField name="code" type="string" required>
  A stable, machine-readable error code.
</ResponseField>

<ResponseField name="detail" type="string">
  A human-readable explanation specific to this occurrence of the problem.
</ResponseField>

<Warning>
Branch your error handling on `code`, not on `status` or `title`. `code` is the stable, machine-readable field this API guarantees; `status` and `title` are for humans and logs.
</Warning>

## Error codes

| `code` | Status | Meaning |
| --- | --- | --- |
| `malformed_request` | 400 | The request couldn't be parsed. |
| `validation_failed` | 400 | The request parsed but a field is invalid. |
| `invalid_credential` | 401 | The API key or token is missing, wrong or revoked. |
| `capability_expired` | 401 | A sandbox capability token expired. Request a new one. |
| `forbidden` | 403 | Authenticated, but not allowed to do this. API keys can't manage organizations, members, invites or API keys. |
| `not_found` | 404 | The resource doesn't exist, or isn't in your organization. |
| `lifecycle_conflict` | 409 | The resource is in a state that refuses the call: a live session with that name, a sandbox that can't be snapshotted yet, or a reused idempotency key with a different request. |
| `snapshot_in_use` | 409 | The snapshot is still referenced. |
| `final_owner` | 409 | An organization's last owner can't be demoted or removed. |
| `payload_too_large` | 413 | The body or file exceeds a limit. |
| `exec_timeout` | 408 | A buffered exec ran past its timeout. |
| `rate_limited` | 429 | Too many requests, or request capacity is exhausted. Honor `Retry-After`. |
| `snapshot_limit_reached` | 429 | You've reached your snapshot limit. |
| `gpu_limit_exceeded` | 429 | The request exceeds your organization's GPU limit. |
| `no_capacity`, `capacity_unavailable`, `gpu_capacity_unavailable` | 503 | No capacity right now. Retry later. |
| `template_preparing` | 503 | The template's image is still being prepared. Retry shortly. |
| `upstream_unavailable` | 503 | A backing service is unavailable. Retry. |
| `internal` | 500 | An unexpected server error. |

This table lists the stable codes. The exact status can vary by endpoint, so branch on `code`.

<Note>
A `404` is also the deliberate response for both "doesn't exist" and "exists but isn't yours" — for example, a well-formed `X-Bonya-Organization-ID` for an organization you don't belong to returns `404`, not `403`, so the API doesn't confirm the organization's existence to non-members. Accepting an invitation token — unknown, addressed to someone else, already consumed, revoked, or expired — is likewise a single indistinguishable `404` rather than a code that would let you tell those cases apart.
</Note>
